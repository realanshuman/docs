Every document you send through Suresign produces a detailed, unchangeable record of its entire journey. This record is called an **audit trail**. It is combined with a **certificate of completion** and a nightly **public record** to create evidence anyone can check. Together they prove who signed, when, and that nothing was altered after the fact.

Think of the audit trail like a bound ledger. Once something is written in it, you cannot rip a page out or rewrite a line without every page after it looking wrong.

## What the audit trail records

For every document, Suresign records every event in a table that cannot be edited:

| Recorded item | What is captured |
| --- | --- |
| Document integrity | A fingerprint (SHA-256) of the original file and the completed file. |
| Parties | Name and email of the sender and every recipient, plus their role and signing order. |
| Events | Date and time in UTC of every send, delivery, open, view, consent, field entry, signature, decline, reminder, cancellation, and expiry. |
| Technical context | The network address and browser details at the time of each event. |
| Signer checks | Whether an access code or emailed code was required, and when each was passed. |
| Signatures | A fingerprint of each signature image, the name and initials it was adopted under, whether it was drawn, typed, or uploaded, and the Signature ID printed with it. |
| Chain | A mathematical lock called a hash, computed for every entry together with the hash of the entry before it. |
| Public record | When completed, the file's fingerprint, reference code, and completion time are added to a public log. No names or content go into it. |

## How the hash chain works, in plain words

A **hash** is a mathematical fingerprint of a piece of data. Change even one comma in a document and the fingerprint becomes completely different. In Suresign, each event in the audit trail is hashed together with the hash of the previous event. This creates a chain where every link depends on the one before it.

If anyone tried to remove an event, insert a fake one, or change a timestamp, every hash after that point would break. The chain is recomputed and checked every time a document is viewed or a certificate is created, so tampering shows up immediately rather than staying hidden.

<Note>
  The audit trail is append-only. That means entries can only be added, never removed or rewritten. Even when a document is permanently deleted, its audit trail stays intact because the chain uses a fixed reference that never moves.
</Note>

## The certificate of completion

When the last person signs, Suresign creates a certificate that includes:

- The document title and unique identifier
- Every party with their name, email address, role, and signing order
- The Signature ID for each signer
- The SHA-256 fingerprint of both the original and the completed file
- The complete audit trail with timestamps, network addresses, and browser details
- When each signer adopted their signature, if they did it in Settings under Signatures
- Any file attachments uploaded by signers
- A count of total fields and completed fields

Anyone holding the signed file can check it at [suresign.si/verify](https://suresign.si/verify). The result shows whether the file is unchanged and displays its entry in the public record.

## The sealed, flattened PDF

The completed PDF is **flattened**, which means filled form fields become part of the page image and cannot be edited back into blank fields. Each page is also stamped with the document identifier and the address [suresign.si/verify](https://suresign.si/verify). This creates a single file that matches the fingerprint on the certificate.

## The nightly public record

Every completed document is added to a public, append-only record at [suresign.si/ledger](https://suresign.si/ledger). Each night, a **checkpoint** of the entire record is published and signed. Because later checkpoints must extend earlier ones, this proves no entry was changed or removed.

The public record holds only three things: a fingerprint, a reference code, and a time. No names, email addresses, or document content ever enter it.

## What this proves

Together, the audit trail, certificate, and public record prove four things:

1. The file you hold is exactly the file that was sealed when signing finished.
2. You can see who was asked to sign, and when each person did.
3. The history behind it is unbroken and unedited.
4. It is in the public record, published every night, so Suresign cannot quietly rewrite history.
